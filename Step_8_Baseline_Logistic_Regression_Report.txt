MODEL GOVERNANCE NOTES

1. The model uses a chronological train/validation/test design.
2. Split boundaries were selected using transaction counts while keeping complete simulation steps together.
3. Threshold selection used validation data only. The final test set remained untouched until evaluation.
4. Logistic Regression used class_weight='balanced' to address severe class imbalance.
5. The selected operating threshold maximises validation F2, placing greater weight on fraud recall.
6. Post-transaction balances, isFlaggedFraud, raw identifiers, zero_amount_flag and the highly simulation-specific amount_exceeds_origin_balance_flag were excluded from the baseline model.
7. Because class weighting changes the probability scale, fraud_score should be treated as a model ranking score rather than a fully calibrated real-world fraud probability.
